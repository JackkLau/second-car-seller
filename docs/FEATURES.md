# 功能与体验

见车围绕“按需选车、逐项核验、费用明确、低负担预约”组织二手车卡片和看车流程。

**当前前端使用8台虚构示例车源，预约也只在本地演示。** 独立后端已提供真实资料接入和存储代码，但尚未完成平台实网抓取与原生 PostgreSQL 联调，不能据此认定四个平台已经接通。后端能力、来源状态和运行方法见 [数据接入文档](./DATA-INTEGRATION.md)，执行证据见 [验证记录](../VERIFICATION.md)。

## 选车与比较

| 功能       | 当前行为                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| 车辆卡片   | 展示车型照片、上牌时间、表显里程、所在地、售价、另列费用、检测资料状态和已知瑕疵                         |
| 筛选与搜索 | 按用途、车价预算、品牌、城市、检测报告筛选；支持多关键词中文搜索、排序和空结果恢复                       |
| 个性化推荐 | 可填写用途、已列费用预算、常乘人数、日常里程、补能条件和优先项；在当前筛选结果内排序并说明理由与不匹配点 |
| 收藏       | localStorage 只保存车辆编号；可切换“我的收藏”，支持刷新恢复和同源多标签同步                              |
| 车辆对比   | 最少两台、最多三台；并排比较价格、费用、里程、检测资料、瑕疵和配置                                       |

推荐使用可解释规则。预算和座位限制优先于一般偏好，不显示虚构的匹配率，不将推荐结果当作车辆安全结论。现阶段没有连接真实用户画像、库存、检测机构、报价或商家系统。

## 车况与针对性看车

详情页按项目区分“已经检查”“已查需关注”“待检测”“资料待核验”，展示结果、日期和来源。轮胎与制动分开记录；部分检查完成不会变成整车全部通过。已检测标记只说明存在示例记录，逐项内容以 [inspections.ts](../src/data/inspections.ts) 为准。

已知缺陷在详情中明确列出。新能源车展示示例电池信息，并提示进一步核实电池状况和相关权益。

用户可以勾选报告核验、补检、瑕疵复核、试驾乘坐、家庭装载、停车体验或纯电专项。每个项目说明需要验证什么、用户能做什么、销售应准备什么，以及可能产生但尚未确认的费用。

## 销售配合与预约

看车清单覆盖到店前资料与报价、到店体验、专业检测及结果解释、整备复检、交付费用确认。这里列出的是**待沟通要求**，不代表销售已经同意、检测已经安排或费用已经报价。

所选项目按车辆保留在当前页面中，带入预约页和本地成功页；用户可以返回详情调整。预约支持选择未来七天的日期与时段，填写演示手机号并完成校验。预约不会发送给商家，也不会收费。

体验流程：

1. 在列表上方展开“按我的需求选车”，填写需求并应用。
2. 查看车辆卡片的适配理由和提醒，进入“查看车况”核对已查与未查项目。
3. 在“把感兴趣，变成有准备的看车”中勾选项目，查看销售配合与费用说明。
4. 点击“带着清单选时间”，核对清单并生成本地预约示例。可使用 **13800000000** 体验。

## 费用口径

| 展示位置       | 金额含义                                                                        |
| -------------- | ------------------------------------------------------------------------------- |
| 目录预算筛选   | 只比较车辆售价，其他费用另列                                                    |
| 个性化需求预算 | 比较“车辆售价＋已列服务费＋过户服务费”                                          |
| 费用明细       | 分别列出车价、服务费、过户服务费与已列费用合计；保险和运输不在合计内            |
| 待报价项目     | 保险、专项检测、电池诊断、整备复检、运输、补能等未知费用使用 `null`，不视为免费 |

已列费用合计不是最终落地总价。后续真实报价需要结合具体车辆、服务范围、支付对象与触发条件确认。

## 数据与隐私边界

前端显示的车源、价格、车况、地点和预约均为虚构展示数据，不是真实在售车源。照片是对应车系的车型示意，可能与虚构年款、配置或颜色不同，不能作为车况证据。

[backend/examples](../backend/examples) 中的人工事实摘录带有真实来源标记，不混入前端，也不代表实时抓取已成功或车辆仍在售。实际检测、保单、出险和维保记录需要各自的来源与获取状态；缺失记录不意味着没有事故或维修。

| 数据                   | 保存范围                                                       |
| ---------------------- | -------------------------------------------------------------- |
| 查询条件               | 保存在 URL                                                     |
| 收藏                   | localStorage 中的车辆编号                                      |
| 用车需求、逐车看车清单 | 当前页面内存，刷新后清除                                       |
| 预约联系方式           | 当前组件内存；不写入 URL、日志或 localStorage，不发出外部请求  |
| 预约结果               | 本地演示；提交成功后清空号码，确认页只显示脱敏号码，刷新后清除 |

## 移动端与可访问性

移动端使用单列卡片、筛选弹窗、可横向滚动的对比表和视口内可滚动的详情/预约弹窗。

交互采用原生表单控件，提供键盘焦点、对话框 Escape 关闭、关闭后焦点恢复、状态播报和减少动态效果偏好支持。实现这些行为不等于完成所有浏览器、真实手机或人工无障碍认证；实际验证范围以 [VERIFICATION.md](../VERIFICATION.md) 为准。
